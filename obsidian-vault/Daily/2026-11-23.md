### The "ChatGPT returns after reboot" theory was wrong

The 14 `ChatGPT.exe` processes are the **Codex** MSIX package
(`OpenAI.Codex_26.1111.9664.0`). Evidence against an autostart:

- manifest startup task: `Enabled="false"`
- no `Run` / `RunOnce` value, no Startup folder entry
- no scheduled task, no service dependency
- `RestartApps = 0` present and effective
- start time 19/11 17:26:18 = **5 minutes after boot**, not at sign-in
  (a startup task fires within seconds)

It had simply been left running. Killed, nothing restarted it.

## Craft Anything ↔ Hermes - the real cause of "nothing happened"

Earlier in this session we assumed the MCP link was broken. The records say otherwise.

| Time | Event |
|---|---|
| 06:01:43 | Builder run starts |
| 06:12:09 | `custom didn't respond in time on any of 3 attempts` - local provider `127.0.0.1:11434` down (Ollama stopped) |
| 06:12:17 | Hermes exits 2, `0 tokens in / 0 out` |
| 06:12:49 | Craft Anything retries automatically |
| 06:33:24 | `Gateway disconnected` again; retry loop every ~90s |

Causes and fixes:

1. **Provider down.** Ollama had been stopped for RAM. Hermes' `model.provider:
   custom` = `http://127.0.0.1:11434/v1`, so all calls failed. Fixed: use
   `tools/agent-preflight.ps1 -StartProvider`.
2. **Wrong model for an agent.** `bonsai-2:4b` has `TEMPLATE {{ .Prompt }}` - no
   chat template. Measured: 57.7 s and ~200 hidden tokens to answer "OK".
   `laya` returns HTTP 400 on chat. Fixed: `hermes config set model.default lfm3:1.7b`
   (verified: "OK" in 20.8 s).
3. **Concurrent Hermes runs collide.** Craft Anything retries; manual `-z` tests
   share one gateway. Rule: one builder at a time (`docs/MCP-WIRING.md`).

MCP itself was never broken: `hermes mcp test craft-anything` - connected in
3.9 s, **38 tools** discovered.

Preflight results (2026-11-23): 7/7 PASS. MCP handshake: 38 tools. OpenCode:
`mcp.craft-anything` enabled. Hermes: `craft-anything` enabled. Model:
`lfm3:1.7b`. `data/knowledge.db`: 107 documents, 388 chunks, 173 headings.

## Never do again

- Do not assume a process name identifies an app: `ChatGPT.exe` was Codex.
- Do not trust an empty `cmdkey` filter; verify with `CredRead` and a real
  auth call.
- `commit`, not working set, is the metric that matters on an 8 GB / 20 GB
  pagefile machine. `ollama app` showed 21 MB WS but 3.6 GB commit.

### Root causes (MCP was NOT one of them)

- **Provider down.** Ollama had been stopped in the memory cleanup above.
  Hermes points at `http://127.0.0.1:11434/v1`, so all calls timed out.
- **Model unfit for an agent.** `bonsai-2:4b` has `TEMPLATE {{ .Prompt }}` —
  no chat template. Measured: 57.7 s and ~200 hidden tokens to say "OK";
  empty content below 64 tokens. `laya` returns HTTP 400 on chat completions.
- **Concurrent one-shots.** Two Hermes runs share one gateway; the second
  gets `Gateway disconnected; turn outcome is unknown`.

`hermes mcp test craft-anything` proved MCP fine: connected in 3.9 s,
**38 tools discovered**. `hermes mcp list` shows it enabled.

### Fix applied

- `hermes config set model.default lfm3:1.7b` (tool-calling, 15.8–20.8 s per
  short reply; real turn: 2,050 in / 34 out in 46.3 s). Backup of config kept.
- Killed the self-retrying `craft-anything.exe` loop; no progress was lost.
- Added `tools/agent-preflight.ps1` (7/7 PASS here) and
  `tools/wire-craft-anything.ps1`, `docs/MCP-WIRING.md`.
- Added `data/` knowledge base: `build-facts.json`, `index.json`,
  `knowledge.db` (SQLite FTS5, 107 docs / 388 chunks / 123 facts),
  `scripts/build_index.py`, `scripts/query.py`.

### Decision for the desktop

On 8 GB CPU-only, use OpenCode (cloud model) for multi-step builds; Hermes with
a local 1.7B cannot prefill a 9k prompt plus 38 tool schemas inside the gateway
window. With 16 GB+ / GPU on the desktop, a 7B–14B local model is viable.
Run `agent-preflight.ps1 -StartProvider` on any workstation before a build.
